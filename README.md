# ProCam Reel Master

Local-only Android recorder + Instagram Reels optimizer. Native CameraX capture,
separate AAC mic track (Bluetooth/wired/built-in), FFT denoise on export.
Videos are never uploaded. Firebase Analytics is used only for anonymous usage
counters (event names + coarse numbers, no filenames, no media).

There are **two ways to use it**:

1. **Web app (works today, no install)** - open the link below on your phone.
2. **Android APK** - full native pipeline (CameraX + FFmpeg export).

## Download the APK

Direct install (no login, no build tools):

```
https://github.com/naveenddu89-sketch/ProCam-Reel-Master/releases/latest
```

- Most phones: `app-arm64-v8a-release.apk`
- Older 32-bit phones: `app-armeabi-v7a-release.apk`

Tap the APK on the phone, allow "Install unknown apps" for the browser, then
open ProCam and grant camera + mic permission.

## Web app

Link (after GitHub Pages is enabled for this repo):

```
https://naveenddu89-sketch.github.io/ProCam-Reel-Master/
```

The web app lives in `docs/` and is plain HTML/CSS/JS - no build step, no server.
Open it in Chrome/Edge/Safari on Android; allow camera + mic. It records with
`MediaRecorder` from a canvas, so the output is exactly 1080x1920 for 9:16
(1080x1080 for 1:1, etc.) at an 18 Mbps target.

What is included:

- live camera preview with 3x3 grid, front/back flip, torch (if the browser
  exposes it), zoom 1x/2x/4x, 30/60 FPS and HD/4K request
- draggable floating teleprompter with speed (up to 180), size and opacity
  controls, a restart button and a full-screen editor for long scripts
  (200k characters)
- long takes are streamed to IndexedDB in 1 s chunks, so multi-minute
  recordings never have to sit in RAM; a take is combined on stop
- local gallery in IndexedDB (thumbnail, size, duration, date), one-tap
  share/download, delete
- mic picker plus a WebAudio chain: high-pass 90 Hz, low-pass 12 kHz,
  compressor, 192 kbps AAC
- installable PWA: use Chrome → "Add to Home screen" once the page is loaded
- all media stays on the phone; nothing is uploaded

Browser limits (these do not apply to the APK):

- Output container depends on the browser: Chrome/Edge on Android produce
  **MP4 / H.264**; other browsers may produce WebM, which Instagram rejects.
  Convert the file or use Chrome for upload-ready reels.
- No FFmpeg, so no `afftdn`/`loudnorm` two-pass export. Audio is cleaned live.
- 4K is a request, not a guarantee - the browser picks the closest camera mode.
- Torch, Bluetooth SCO routing and some mic labels depend on the OS/browser.

### Publish with GitHub Pages

1. Push `docs/` to `main`.
2. Repo → **Settings → Pages** → Source: *Deploy from a branch* →
   Branch: `main`, folder: `/docs` → **Save**.
3. Wait ~1 minute; the URL above becomes live. Camera needs HTTPS, which Pages
   provides automatically.

### Run the web app locally

```powershell
# any static server works; camera works on http://localhost
npx serve docs
# or: python -m http.server 4173 -d docs
```

### Maintenance (near zero)

- Static files only: no npm, no build step, no server, no database, no API keys.
- GitHub Pages redeploys automatically on every push to `main`.
- The service worker is network-first, so new files reach users without a cache
  version bump.
- The APK workflow pins Flutter `3.47.9` and every Dart package; `android/gradle.properties`
  keeps the AGP 9 legacy DSL. Bump these only when you deliberately upgrade.
- Recurring work: none. Optional: glance at the Actions tab occasionally.

## Build & run (Windows PowerShell)

```powershell
flutter doctor
flutter create --platforms=android --org com.procam --project-name procam_reel_master .
flutter pub get
flutter run -d <DEVICE_ID>          # flutter devices
```

Release APK (per-ABI, much smaller):

```powershell
flutter build apk --release --split-per-abi
adb install -r build\app\outputs\flutter-apk\app-arm64-v8a-release.apk
```

Requirements: Flutter 3.27+, JDK 17, Android SDK 35+, real device
(emulators usually lack 4K, SCO and a usable mic).

If `flutter create` generated a Groovy `android/app/build.gradle` instead of
`.kts`, keep the generated file and merge the `android {}` values + the CameraX
`dependencies` block from `build.gradle.kts` into it.

## Firebase Analytics (optional at runtime)

`lib/firebase_options.dart` is a placeholder, so `Analytics.init()` fails quietly
and every `log()` call becomes a no-op. The app builds and runs fully offline in
that state. Enable telemetry once Flutter is installed and `flutter create` has
created the Gradle scaffold:

```powershell
dart pub global activate flutterfire_cli
flutterfire configure --project=procam-reel-master
flutter pub get
```

`flutterfire configure` registers `com.procam.reelmaster` in the project,
overwrites `lib/firebase_options.dart` with real keys, downloads
`google-services.json` and adds the `com.google.gms.google-services` plugin to
the Gradle files.

| Event | Params |
|---|---|
| `record_start` | aspect, quality, torch, zoom, mic, teleprompter |
| `record_stop` | duration_s, finalized |
| `aspect_change`, `quality_change`, `mic_select` | chosen value / mic type |
| `export_start`, `export_done`, `export_failed` | fps, seconds, mb, error |
| `share` | target, source, ok |
| `screen_view` | automatic via `FirebaseAnalyticsObserver` |

No file paths, mic names or media are ever sent. To disable telemetry later,
set `isConfigured = false` (or delete the generated keys) - no other change
needed.

## Capture pipeline (why it stays cool on 3 GB)

- Only **Preview + VideoCapture** are bound. No `ImageAnalysis`, no preview
  frame copies, no OpenGL in Flutter.
- Recording is hardware H.264 through MediaCodec. Bitrate pinned:
  20 Mbps @ 1080p, 45 Mbps @ 4K. CameraX's default mic is bypassed.
- Audio is a second, tiny pipeline: `AudioRecord` (48 kHz mono) -> AAC-LC
  192 kbps in `MicRecorder.kt`, ~4 KB buffer, no per-frame allocations.
- Aspect switching rebinds use cases **only while idle**; it is rejected
  during a take so the encoder never restarts mid-recording.
- Long takes: the screen is kept awake with `FLAG_KEEP_SCREEN_ON` while
  recording, free storage is checked before a take starts, and a playable
  partial file is kept if CameraX finalizes with an error (e.g. storage full).
- The teleprompter scrolls with a vsync `Ticker` and `jumpTo` - zero rebuilds
  per frame - and supports long scripts (200k characters) plus speed up to
  180 px/s.

## Export pipeline (Reels spec)

`lib/services/video_exporter.dart` builds:

- `scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920`
  (crop-to-fill, no letterbox bars)
- `fps=30|60` constant frame rate
- `libx264`, High profile, `-b:v 18M -maxrate 20M -bufsize 36M`
- `-color_primaries bt709 -color_trc bt709 -colorspace bt709 -color_range tv`
- `afftdn=nr=12:nf=-35:tn=1` -> `highpass=90` -> `lowpass=12000` ->
  `loudnorm=I=-14:TP=-1.5:LRA=11` -> AAC 192 kbps mono
- `-movflags +faststart` so Instagram can read the moov atom instantly
- `-threads 4` caps x264 memory on low-RAM phones
- a 60 minute export timeout so long takes finish instead of being cancelled

`audioOffsetMs` from CameraX keeps lip-sync (audio is trimmed or delayed by the
measured start delta).

## Mic sources

`AudioRouteManager` lists real inputs (`TYPE_BUILTIN_MIC`, `WIRED_HEADSET`,
`USB_DEVICE/HEADSET`, `BLUETOOTH_SCO`) and calls
`AudioRecord.setPreferredDevice()` for the selected one. Bluetooth also raises
SCO mode. Denoise is applied at export, so the recorded master stays dry and
re-editable.

> Bluetooth SCO is 16 kHz-class audio. For voice reels a wired lav or the
> phone's built-in mic is usually cleaner; the app shows both so you can pick.

## Tuning

| Knob | File | Default |
|---|---|---|
| Reels bitrate | `video_exporter.dart` | 18 Mbps (max 20) |
| FPS | export sheet | 30 (60 on stronger phones) |
| Denoise strength | `afftdn=nr=` | 12 dB |
| Loudness | `loudnorm=I=` | -14 LUFS |
| Capture bitrate | `CameraEngine.kt` | 20 / 45 Mbps |
| Teleprompter speed | overlay panel | 26 px/s |

## Dropping into an existing app

1. Copy `lib/services`, `lib/widgets`, `lib/screens`, `lib/core`, `lib/models`
   into your project and fix relative imports if your tree differs.
2. Copy `android/app/src/main/kotlin/com/procam/reelmaster/**` into your
   package (rename the package, or keep the `com.procam.reelmaster` subpackage).
3. Merge `AndroidManifest.xml` permissions, `<queries>`, the `FileProvider`
   block and `res/xml/file_paths.xml`.
4. Merge the CameraX `dependencies` and `minSdk = 24` into your app Gradle file.
5. `flutter pub get` and run. `MainActivity` must register the
   `procam/engine`, `procam/engine_events` and `procam/files` channels.

`flutter create` only fills in missing scaffolding (Gradle wrapper, settings,
themes, launcher icons); it does not overwrite the existing `lib/` or `android/`
sources here. If your Flutter version does replace `MainActivity.kt`, restore it
from this repo before building.

## Known limits

- Export always targets the 1080x1920 Reels spec. The aspect chips change the
  *capture* framing (the 9:16 preview matches the Reels crop); a 16:9 master
  is recorded with the wider sensor crop and is still delivered as a Reel.
- Aspect ratio changes are instant while idle; switching during a take is
  blocked on purpose (restarting the encoder would corrupt the MP4).
- Bluetooth SCO is narrowband. Prefer a wired lav for the cleanest voice.
- Export is CPU-bound. A 60 s 1080p30 take takes roughly 40-80 s on a
  Snapdragon 6-series; keep the app foregrounded.
- `ffmpeg_kit_flutter_new_min_gpl` is the smallest build that still has x264 +
  `afftdn` + `loudnorm`. Do not swap it for `_min` (no libx264).
- Firebase Analytics adds ~300 KB per ABI and needs network at runtime; if
  `flutterfire configure` has not run, the app stays fully offline.
